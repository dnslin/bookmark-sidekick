# 标签整理 正文搜索与稍后读验证记录

日期：2026-10-21。分支：`codex/library-upgrade`。

三项功能已按确认方案实现。沿用现有系统字体、颜色、书签行和「最近／分类／待确认」导航。完整自动检查、隔离浏览器验证及真实 Chrome 扩展加载、站点权限与 MV3 后台重启验证均通过。

## 实现结果

| 功能 | 当前行为 |
| --- | --- |
| 手动标签 | 支持输入、已有标签建议、移除、清空与保存；每条最多 20 个，每个最多 32 字符；未回车输入也会提交；保存期间的新编辑保留。 |
| 批量整理 | 只选择当前结果；批量改分类、增删指定标签和安排阅读；默认保持不变；取消保留选择；失败保留面板与草稿；已删除书签明确跳过。 |
| 正文搜索 | 本地 Worker 执行；复用两套 Fuse 索引；中文分词、多词跨字段 AND、元数据模糊与正文精确包含；片段来自实际正文，点击进入快照定位。 |
| 稍后读 | 主动加入后进入待读；本地快照支持继续阅读与位置恢复；滚动到底不自动已读；明确点击后完成；移出只改阅读安排。 |
| 数据与备份 | Dexie v2 一次升级补默认阅读字段；v3 备份包含手动标签、阅读状态、正文和位置；明确拒绝 v1/v2。 |

手动整理继续使用已有的整条 AI 保护。阅读更新不增加 AI 内容版本，也不取消分类任务。正文快照的版本保持单调，防止旧阅读页在连续保存或备份恢复后回写位置。

列表只显示阅读状态；具体阅读百分比在阅读菜单、详情和阅读页显示，避免为了列表展示位置而读取整库快照正文。短侧栏的批量表单整体滚动，字段和操作区不互相遮挡；阅读页底部控制保持可见。

## 固定规模搜索验证

以下是本机 Node 的一次固定语料模拟，包含实际 Fuse 建索引与查询。时间不包含 IndexedDB 读取、线程通信和界面渲染，不代表用户真实书签库的完整交互时间。

| 规模 | 首次查询含建索引 | 索引就绪后的查询 |
| --- | --- | --- |
| 1,000 篇，4,011,354 字符 | 48.37 ms | 12.75—21.73 ms |
| 10,000 篇，40,113,534 字符 | 393.71 ms | 119.10—183.12 ms |
| 单篇 499,941 字符，命中正文末尾 | 2.89 ms | 正确返回命中片段 |

以上是合并前修复后的末次独立模拟。一万篇的「状态 恢复」查询实际返回全部一万条，耗时 166.12 ms。正文没有截断；只限制展示片段长度。对应模拟的堆使用增量约 136.68 MiB，并非浏览器峰值内存测量。修复前的另一次同机热查询曾达到 396.62 ms；这些数值受机器和并行任务影响，不能把单次低于 300 ms 当作稳定保证。

## PR #7 合并前评审与边界修复

对数据与备份、搜索、界面与阅读分别进行独立代码评审，覆盖正确性、简洁性、模块边界、安全和性能。数据层未发现阻塞；新增的长正文边界检查发现并修复了以下问题。

| 问题 | 修复与回归 |
| --- | --- |
| 400,000 字符的密集短词正文，查询 `a` 时抛出 `Maximum call stack size exceeded`，Worker 整次失败 | `14a21c8` 关闭正文 Fuse 的全量命中范围返回，只为展示窗口提取原文范围。保留双 Fuse、完整正文和全部命中结果；先新增失败的纯搜索和实际 Worker 回归，再验证修复通过。 |
| `İ quartz end` 中大小写转换扩展字符后，高亮错位为 `uartz `，长文还可能丢失命中片段 | 同一提交按原文 UTF-16 偏移生成片段，只在小窗口需要时映射扩展字符。覆盖匹配前扩展、匹配字符自身、长文末尾、表情边界和超长词。 |
| 普通打开接近 500,000 字符的快照也构建整篇逐字符定位表，实际在界面线程同步执行 | `96d6134` 让无搜索词阅读直接跳过；有查询时按节点保留规范化字符串，只扫描实际命中节点的原文范围。空词跳过回归先失败后通过，保留跨行内节点、段落、空白、表情及大小写扩展的定位语义。 |

修复后由另一名评审独立复核通过，未发现剩余 P1/P2。除现有测试，还以 20,000 组多节点文本对照阅读结果、1,400 次搜索对照命中与排序、1,000 组 Unicode 文本检查片段范围。最终由主代理统一执行 `npm run check`，160 项测试、类型检查和构建全部通过。

可重跑命令：

- `node --experimental-strip-types scripts/benchmark-search.mjs`：除固定规模外，新增重复短词与 Unicode 末尾边界。末次模拟 400,000 字符短词查询 4.58 ms，499,986 字符扩展字符末尾查询 25.46 ms，结果及范围断言通过。
- `node --experimental-strip-types --expose-gc scripts/benchmark-reader.mjs`：固定 500,000 字符；空词 0.09 ms、末尾跨节点定位 48.03 ms，堆使用增量分别为 0.01 / 21.98 MiB。旧实现的同规模诊断约 2.6—4.1 秒。脚本校验实际范围，不设机器相关的耗时断言。

这些基准不包含 IndexedDB、线程通信、DOM 遍历、HTML 清洗、布局和绘制，堆差值也不是峰值。Fuse 的 include matcher 内部仍会枚举临时位置；本次没有修改上游库，也没有声称消除了全部内部成本。
