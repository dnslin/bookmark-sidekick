# 拾签手动整理 全文搜索与稍后读方案

状态：用户已确认，已实施并完成隔离验证。日期：2026-10-21。

这一版让用户可以自己整理标签、一次整理多个书签、根据正文找回文章，以及完成稍后阅读。保留当前侧边栏的品牌、颜色、字体、顶部结构和「最近／分类／待确认」导航。

三项功能已落地，实施与验证结果见 [LIBRARY-UPGRADE-VALIDATION.md](LIBRARY-UPGRADE-VALIDATION.md)。前期原型采用示例数据，用于确认入口、布局和操作反馈；它不作为真实扩展运行证据。

## 一 交付范围与模块边界

| 模块 | 负责什么 | 依赖 |
| --- | --- | --- |
| manual-organization | 单条标签编辑；多选后修改分类、添加或移除标签 | 现有详情、分类、标签、后台消息和手动整理保护 |
| read-later | 待读、阅读中、已读；阅读位置恢复；单条和批量设置 | 现有书签与正文快照 |
| full-text-search | 搜索已保存正文；展示命中片段；打开快照定位 | 现有 Fuse、快照；将前两项状态作为可组合筛选 |

建议按「单条标签 → 稍后读 → 批量整理 → 全文搜索 → 综合验证」交付。标签与阅读字段的备份支持随对应步骤一起完成，不留到最后补。每一步都保留可正常使用的完整流程。

首版批量操作包含：改分类、添加标签、移除标签、加入稍后读、标记已读、移出阅读列表。不包含批量删除、批量移动原生文件夹、批量抓取正文。

全文搜索只针对已保存的本地正文。不请求网页，不使用模型，不搜索图片中的文字，不增加语义问答。阅读位置只跟踪本地快照。

## 二 当前实现与设计依据

- `src/components/Detail.tsx` 目前能编辑标题和分类，标签只能查看。
- `src/messages.ts` 的 `EDIT` 只有标题和分类；`APPLY` 批量确认 AI 建议，不是通用批量整理。
- `src/search.ts` 使用 Fuse 搜索标题、网址、分类、标签和摘要，没有包含 `Snapshot.text`。
- `src/domain.ts` 的书签没有阅读状态；`Snapshot` 已保存 HTML、纯文本和抓取时间。
- `src/service.ts` 的手动编辑会增加 `revision`、设置 `manual`，并删除该条未完成任务和建议。自动分析会检查版本，避免覆盖手动整理。
- `src/backup-format.ts` 目前把每条书签的标签数限制为 3。该限制需要与手动标签功能一起调整。
- `docs/UI-REDESIGN.md` 和 `docs/ui-home.png` 是当前视觉依据。新增控件沿用现有灰底、蓝色操作、细分隔线和紧凑列表。

参考成熟产品的具体做法：Raindrop 在搜索结果中支持检索保存的正文；Anybox 用阅读列表区分要读的内容与完成阅读的内容。本方案只借鉴使用习惯，不引入其账号、云端或其他产品模块。[Raindrop 搜索说明](https://help.raindrop.io/using-search)，[Anybox 稍后读说明](https://anybox.app/zh-CN/read-it-later)。

## 三 手动标签与批量整理

### 单条标签编辑

详情页中，「标题／分类」下方增加可编辑标签区。标签以当前样式的浅色标签显示，每个标签带移除按钮。

1. 输入后按回车或逗号添加；也可点选书签库里已有的标签。
2. 前后空白会被清除。重复判断不区分英文大小写，保留先添加的写法。
3. 单个标签沿用 32 字符限制。手动整理最多 20 个标签，AI 输出继续最多 3 个。达到上限或重复时在编辑区提示，不静默丢弃输入。
4. 点击「保存修改」后，才更新书签。尚未按回车的非空输入也纳入本次保存；取消或返回不写入草稿。
5. 清空所有标签是一种有效修改。保存失败保留已输入的标题、分类和标签，允许重试。

沿用当前的整条手动整理保护。修改分类或标签后，后台不再自动覆盖该条的分类、标签和摘要；主动重新分析仍生成待确认建议。确认建议表示用户接受这次结果，可以覆盖整理字段。首版不新增逐字段锁或规则系统。

只修改标签时，不提交旧标题或旧分类覆盖后台的新值。当前表单已有未编辑字段跟随最新数据的行为，但后台 `EDIT` 仍接收完整标题和分类；本次改为只提交并写入用户实际修改的字段。与 AI 整理有关的修改继续增加 `revision`，使已过期的在途结果无法覆盖新值。

### 进入与退出整理

- 最近列表、分类筛选、标签筛选、搜索结果、稍后读列表的标题右侧显示「整理」。
- 点击后出现行复选框、顶部「选择当前结果」和底部操作条。普通浏览时隐藏这些控件。
- 行点击改为选择，避免选择过程中打开网页。全选只包含当前筛选结果，不包含隐藏书签。
- 底部显示「已选择 N 项」和「批量修改」。未选择时不能提交。
- 修改搜索词、切换筛选或主导航时，退出整理并清空选择。详情返回列表时保留原来的查询条件。

### 批量修改面板

| 字段 | 默认 | 可选操作 |
| --- | --- | --- |
| 分类 | 保持不变 | 设置一个现有分类 |
| 标签 | 保持不变 | 添加指定标签；移除指定标签 |
| 阅读安排 | 保持不变 | 加入稍后读；标记已读；移出阅读列表 |

「添加标签」按每条书签提交时的最新标签合并，不整组替换。「移除标签」只移除指定项，不影响其他标签。首版不提供容易误清空数据的「替换全部标签」。

面板显示本次改动预览。没有有效改动时，应用按钮禁用。只改阅读安排不触发手动整理保护，也不影响在途 AI 任务。

提交时使用当前仍存在的书签记录；已删除记录跳过，返回已处理及跳过数量。本地写入失败时回滚该次写入，保留面板与选择，不显示成功。若任一书签合并后超过标签上限，本次不写入，明确提示调整标签。

成功后关闭面板、清空选择、退出整理，保留当前搜索和筛选，并展示结果。取消只关闭面板，保留选择。上述操作只修改拾签的整理数据，不移动 Chrome 原生文件夹。

## 四 正文全文搜索

### 入口与结果

沿用当前搜索框，提示文案改为「搜索书签与正文」。默认同时检索标题、网址、分类、标签、摘要与已保存正文，不增加独立搜索页面。

- 搜索与当前分类、标签、稍后读筛选取交集。清空搜索词后返回该筛选下的普通列表。
- 中文按词检索，英文不区分大小写。多个查询词需要全部命中，可以分布在不同字段；增加查询词会缩小结果。
- 元数据保留轻度模糊匹配。正文采用精确词匹配，不进行语义推断。
- 优先显示标题和标签命中，其次是网址、分类与摘要命中，再其次是仅正文命中。同等相关度按收藏时间倒序。同一书签只显示一次。
- 正文命中时展示一段来自真实快照的上下文，通常约 80—120 字，并标出命中词。命中在文章末尾也要能找到。
- 点击命中片段，打开对应快照并定位到第一个相关段落。普通书签标题仍打开原网页，详情入口仍编辑书签。
- 结果页显示本次已搜索的正文份数。没有快照的书签仍可通过其他字段找到，不暗示其正文已经被搜索。

首次加载正文时显示「正在准备正文搜索」；完成后替换为正式数量。失败时显示可重试的错误，不能把正文搜索失败伪装成「没有结果」。新查询已开始后，旧查询不能回写覆盖新结果。

### 复用现有搜索能力

已安装的 Fuse 7.5.0 支持 `useTokenSearch`、自定义 `tokenize` 和 `includeMatches`。中文分词使用浏览器内置的 `Intl.Segmenter`，分词函数在 Worker 内部创建。不新增全文搜索依赖，不自建倒排索引。能力依据：[Fuse 分词搜索说明](https://www.fusejs.io/token-search.html)。

同一 Worker 中分开维护元数据和正文两个 Fuse 索引：元数据保留现有模糊阈值，正文设置精确匹配阈值。查询使用相同分词规则，每个词取两类命中书签的并集，再对所有查询词取交集，允许不同词命中不同字段。分开索引是因为 Fuse 的阈值属于整个实例，单个实例不能直接为不同字段设置不同的精确度。命中字段用于结果分组，相关度和收藏时间用于组内排序。实施时用外部结果测试验证这一完整规则。

正文处理放在专用 Web Worker，也就是独立于界面运行的浏览器线程。第一次输入搜索词时才准备正文数据与索引，避免打开侧栏就承担全库正文处理。

Worker 通过 Dexie 游标逐条读快照，仅保留纯文本和必要的搜索字段。当前 HTML 与纯文本在同一行，因此读取时仍会短暂反序列化 HTML；不把整库 HTML 数组留在内存，也不把它传给界面。首版不新增重复存储正文的搜索表。

索引按书签内容与快照变化更新。选择状态、阅读位置和普通页面跳转不重建正文索引。正文不做额外截断，覆盖当前已保存的 `Snapshot.text` 全部内容。最终片段由纯文本和字符位置生成，使用文本节点高亮，不把搜索词拼接成未经处理的 HTML。

## 五 稍后读

### 阅读状态

使用一个明确的阅读状态字段，不增加独立队列表或一组相互重复的布尔值。

| 状态 | 用户看到什么 | 进入方式 |
| --- | --- | --- |
| `none` | 没有加入阅读列表 | 所有旧书签和普通新收藏的默认状态；主动移出阅读列表 |
| `later` | 待读 | 主动加入稍后读；将已读文章重新加入待读 |
| `reading` | 阅读中 | 已在稍后读的书签打开本地快照 |
| `read` | 已读 | 用户主动点击标记已读 |

「最近」页下增加「全部／稍后读」二级筛选。「稍后读 N」的数量只计算待读与阅读中。进入后默认显示待阅读内容，先列阅读中，再列待读；可以切到已读记录。

列表新增始终可用的时钟入口。详情页新增「阅读安排」。二者均支持加入稍后读、标记已读、移出阅读列表。批量面板使用相同的状态规则。

- 旧书签不会自动全部进入稍后读。普通收藏也不自动入队。
- 打开原网页不改变阅读状态。未加入稍后读的书签打开快照，也不自动入队。
- 滚动到底部不会自动标记已读。完成阅读由用户明确操作。
- 标记已读后，从当前待阅读列表移出，但保留原生书签、标签与快照；可在已读中找到。
- 移出阅读列表设置为 `none`，不删除书签和快照。
- 重复加入已经待读或阅读中的书签，不打断其进度。已读文章重新加入待读时重置阅读位置。

### 继续阅读

快照增加 `progress`，范围 0—1，表示该快照的阅读位置。阅读状态存在书签上，阅读位置存在快照上，避免滚动时反复更新整张书签列表。阅读位置与「标记已读」常驻底部，用户无需滚回文章顶部完成阅读。

滚动停止后约 500 ms 保存；持续滚动时最多每 2 秒保存一次。离开阅读页时补写最新位置。打开同一快照时恢复位置；从搜索命中片段进入时，优先定位命中位置。

阅读状态只补丁更新 `Bookmark.readingState`。位置写入先核对当前快照的 `capturedAt`，再仅更新 `Snapshot.progress`，不提交旧的整行书签或快照对象。同一网址重新保存快照后位置归零，保留用户的阅读状态；旧阅读页面不能把位置写到新快照。原生书签网址变化时，清除旧快照及阅读安排，沿用现有的内容失效处理。

没有快照的书签仍能加入稍后读、打开原网页和手动标记已读；页面不显示无法恢复的阅读百分比。

## 六 界面原型

原型沿用当前的系统字体、灰色搜索框、蓝色文字操作、三段导航与底部统计。「全部且没有搜索词」保留日期分组；无搜索词的稍后读按阅读中／待读分组，组内按收藏时间倒序；所有搜索结果均平铺按相关度排序，不再按日期分组。

| 位置 | 新增交互 | 与现有界面的关系 |
| --- | --- | --- |
| 最近列表 | 全部／稍后读；整理；时钟入口 | 保留原三段主导航，不新增第四段 |
| 书签详情 | 标签编辑、已有标签建议、阅读安排 | 放在现有标题与分类字段之后 |
| 整理状态 | 行复选框、当前结果全选、底部数量与修改按钮 | 仅整理时占用空间 |
| 批量面板 | 三组默认保持不变的字段、改动预览 | 复用现有控件和蓝色主要操作 |
| 搜索结果 | 命中片段、正文覆盖数量 | 保留原搜索框与书签行 |
| 快照阅读 | 继续阅读、位置、标记已读 | 保留现有正文快照提示和阅读排版 |

优先检查宽度 430、360、320 px，浅色与深色，以及短高度侧栏。复选框、时钟、详情入口均可使用键盘操作。面板支持 Escape 取消、焦点留在面板内，关闭后返回触发入口。长标题截断但保留完整可访问名称，标签允许换行。

交互原型中的示例文章仅用于演示搜索和阅读，不代表来源网站的实际内容。原型演示的检索不是生产搜索引擎验证；真实 AI、Chrome 权限、后台进程和持久化需在实施阶段单独验收。

## 七 数据与文件改动建议

```ts
type ReadingState = 'none' | 'later' | 'reading' | 'read';

// Bookmark 新增 readingState；Snapshot 新增 progress。
// 沿用已有 manual 和 revision，不引入字段锁或额外整理状态机。
```

- `src/domain.ts`：阅读状态、标签规范化、批量增删规则及手动整理应用规则。
- `src/db.ts`：使用 Dexie 一次版本升级，补齐旧书签的 `readingState: 'none'` 与旧快照的 `progress: 0`，保留已有内容；正常读写只使用新结构。
- `src/messages.ts`、`src/service.ts`：字段补丁、批量整理、阅读状态与位置更新；阅读改动不增加 AI 内容版本、不取消 AI 任务。
- `src/components/Detail.tsx`、`src/App.tsx`、`src/library.ts`：单条编辑、选择范围、列表筛选与阅读状态展示。
- `src/components/TagEditor.tsx`、`BulkEditor.tsx`：拆成两个有清楚职责的组件，不把全部交互堆进 `App.tsx`。
- `src/search.ts`、`src/search.worker.ts`：复用 Fuse，分离查询协调与后台正文检索；返回书签 ID、相关度、命中字段和片段位置。
- `src/components/Reader.tsx`：位置保存与恢复、命中定位、已读操作。
- `src/backup.ts`、`src/backup-format.ts`：导出与恢复阅读状态、位置和最多 20 个手动标签；继续使用已有的唯一匹配规则，避免同网址的不同书签交换数据。
- `tests/`：继续使用现有 Node 测试运行器与组件测试方式。测试通过对外结果断言，不镜像内部实现。

数据库升级只补齐已有数据，不新建迁移框架，不保留日常运行的双结构读写分支。书签删除时一并删除其快照位置，沿用现有删除清理。

正文定位需要单独做小范围验证：纯文本的字符偏移不能直接当成 HTML 字符串偏移。阅读组件遍历清洗后的正文文本节点，按相同的空白规范化规则建立位置映射，再定位和高亮对应段落。遇到旧快照纯文本与排版内容不一致、无法定位时，明确提示「已打开快照，未能定位命中段落」，不能假装已经定位成功。

备份格式建议升为 v3。按照项目不默认保持兼容的要求，新版只接受 v3，移除原 v1/v2 的导入分支；选择旧格式时明确提示不支持，不静默丢失新字段。**这会使旧备份无法直接导入新版，是确认本方案时需要一并接受的格式变化。**

## 八 分步交付与验收

| 步骤 | 交付结果 | 本步必须验证 |
| --- | --- | --- |
| 1 单条标签 | 可添加、移除、清空、保存标签；搜索和分类页同步更新；备份支持 20 个标签 | 重复与上限提示；失败保留草稿；在途 AI 不覆盖手动修改；标签备份往返 |
| 2 稍后读 | 加入、继续阅读、标记已读和移出完整可用；同步完成新字段备份 | 旧书签不入队；原网页不自动已读；重开恢复；新快照重置位置；阅读字段备份往返 |
| 3 批量整理 | 在现有筛选结果上选择并修改整理信息 | 全选范围；逐条保留旧标签；取消无写入；删除与写入失败反馈 |
| 4 全文搜索 | 正文可搜、能看片段、能打开定位 | 中文、多词、长正文末尾、重复去重、筛选交集、旧查询不覆盖新查询 |
| 5 综合验证 | 三项功能可组合使用，文档与最终界面一致 | 完整备份往返及原生书签身份匹配；阅读操作不干扰 AI；主题、窄宽度、短高度与键盘 |

必须覆盖的跨功能场景：

1. AI 正在分析时清空标签，晚到结果不能覆盖；同一时刻只加入稍后读，AI 则应正常完成并保留阅读状态。
2. 对不同旧标签的三条书签批量加一个标签，每条旧标签仍保留；移除指定标签后，其他标签不变。
3. 选中的一条书签被外部删除，其余项正常处理，明确报告跳过项；存储异常时不得出现部分成功假象。
4. 搜索只能在正文末尾出现的词，正确展示真实片段；点击后定位；返回后保留搜索和筛选。
5. 第一条查询慢、第二条快时，最终只展示第二条结果；准备或查询失败时可见失败状态。
6. 滚动到底部仍为阅读中；点击标记已读后离开待读队列；再次加入待读从头阅读。
7. 阅读页打开时重新保存快照，旧位置不能覆盖新快照；快照阅读位置更新不重建正文索引。
8. 备份恢复后，20 个手动标签、阅读状态、位置和正文保持对应；相同网址的多个原生书签不会互换数据。

实施时运行：`npm run typecheck`、`npm test`、`npm run build`、`git diff --check`。也可以使用 `npm run check` 执行前三项。相关回归测试必须实际执行后才能记为通过。

搜索另用固定样本验证：1,000 篇约 400 万字符和 10,000 篇约 4,000 万字符；包含中英文、多词与单篇 50 万字符边界。记录首次准备耗时、后续查询耗时、内存和界面响应，不用模拟耗时宣称真实用户库表现。目标是准备时输入和取消仍可用；普通查询在索引就绪后尽量于 300 ms 内给出结果，超出时保留查询状态并记录数据，不能靠截断正文满足目标。
