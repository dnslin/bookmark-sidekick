# 书签流程优化

范围来自本次代码审查及用户的「优化」指令。保留现有功能和界面布局，不新增数据库结构或生产依赖。

## 验收标准

| 模块 | 改动 | 验收 |
| --- | --- | --- |
| 备份 | 按网址、文件夹和标题消除重复书签匹配歧义 | ID 顺序变化不串分类；无法唯一匹配的条目跳过；现有唯一网址仍可恢复 |
| 编辑 | 保留用户修改的字段，同步未修改的字段 | 后台暂停不清空设置草稿；外部书签更新不导致旧字段回写；成功保存/恢复只清除已提交的草稿；保存期间的新输入保留在设置页 |
| 同步 | 合并待执行的同步、导入结束统一同步、只写变化记录 | 导入期间无逐条全量写入；不变数据不写入；标题、网址、移动和删除仍正确同步 |
| 搜索 | 复用索引，待确认建议按 ID 连接书签 | 搜索顺序和筛选结果一致；书签变化会更新索引；建议顺序不变 |
| 任务 | 使用已有状态索引限制领取数量 | 待处理和过期任务能继续；未过期/失败任务不领取；重试和撤回授权行为不变 |
| 加载 | 设置、备份和阅读功能按需加载 | 初始脚本小于原来的 629.28 kB；相关页面和操作正常 |

实施顺序：备份、编辑和后台独立完成；随后整合搜索与按需加载；最后执行完整验证。

## 验证方法

- 源码位于 `src/` 和 `entrypoints/`，测试遵循现有 `tests/*.test.mjs`、Node 测试运行器和 TypeScript 编译方式。
- 回归测试先在原实现上失败，再验证修复后的结果。浏览器和模型边界使用隔离数据；真实浏览器另外检查 React、IndexedDB 和页面加载。
- `npm run check` 执行类型检查、全部测试和生产构建；`git diff --check` 检查修改格式。
- 性能对比使用相同模拟规模、相同采样方式；不把模拟结果当作真实用户交互速度。
- 不连接用户模型，不修改用户浏览器的原生书签，不发布或推送。

## 原实现基线

- `npm run check`：类型检查通过，52 项测试通过，构建通过。
- 初始侧边栏脚本：629.28 kB；构建有超过 500 kB 的提示。
- 内存替身中，100 条书签、100 次创建事件和一次显式同步：101 次整树读取、10,100 次书签写入。

## 完成结果

基础提交：`540127eb6c4669a48ec6b0c2fa99ddd6f5be340a`。工作分支：`codex/optimize-bookmark-flows`。

- 备份按「网址、文件夹、标题」「网址、文件夹」「网址」依次匹配。每轮要求备份条目和本地书签双方唯一，先保留精确匹配，再处理剩余条目。
- 设置和详情只保存用户编辑过的字段覆盖。未编辑字段跟随最新数据，失败保留草稿，成功只清除未再修改的已提交字段。设置保存期间发生新输入时保留页面；普通成功保存仍返回首页，测试连接仍留在设置页。
- 合并排队中的同步请求。运行期间收到的新请求安排下一次读取，以免显式刷新返回旧数据。批量导入结束后统一同步，只批量写入发生变化的记录。
- 搜索在相同集合上复用 Fuse 索引，空查询不建索引。待确认列表用 ID 映射连接书签，避免每条建议遍历整张列表。
- 任务领取使用已有 `status` 索引，再检查运行任务是否过期，每批最多六项。不新增索引或数据库版本。
- 设置、备份和阅读代码按需加载。初始侧边栏脚本为 593.71 kB，减少 35.57 kB（约 5.7%）。总产物仍约 1.14 MB，超过 500 kB 的构建提示仍存在。

### 实际验证

| 命令或检查 | 结果 |
| --- | --- |
| `npm run check` | 类型检查通过；90 项测试通过；Chrome 生产构建通过 |
| `git diff --check` | 通过 |
| `node scripts/benchmark-search.mjs` | 10,000 条书签、连续 8 次查询，2 轮预热后交替采样 10 轮；中位耗时 388.30 → 307.55 ms；索引构建次数 8 → 1 |
| `node tests/helpers/backend-benchmark.mjs /tmp/bookmark-sidekick-service-before-backend.ts` | 使用基础提交的 `src/service.ts` 对比；每个场景 1 轮预热、7 次采样；详见下表 |
| ego-browser 隔离页面 | 生产产物的实际 React、Dexie、IndexedDB 与页面交互通过，见下述覆盖范围 |

后台对比使用内存数据库及 Chrome API 替身。以下读取量和写入量有固定输入，中位耗时仅用于对比这组模拟场景。

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 100 次创建事件，100 条书签，一次显式同步 | 整树读取 101 次，写入 10,100 条，26.93 ms | 整树读取 1 次，写入 100 条，0.24 ms |
| 100 条批量导入，一次显式同步 | 整树读取 102 次，写入 10,200 条，25.96 ms | 整树读取 1 次，写入 100 条，0.21 ms |
| 120 条待处理、1,000 条失败、1 条未过期任务 | 读取 22,281 条任务，14.34 ms | 读取 121 条任务，3.02 ms |

任务场景两侧都完成 20 次模型调用并生成 120 条草稿。性能优化没有通过减少处理量获得结果。搜索耗时仍包括实际模糊匹配和排序，不代表单次按键或完整页面的响应时间。

浏览器检查覆盖：

- 初始页面只加载侧边栏脚本；打开阅读、设置及备份操作后，分别加载对应脚本。
- 搜索 TypeScript 返回正确书签；待确认建议跳过无对应书签的条目，切换、忽略和确认后正确更新。
- 后台设置变化同步未编辑的模型字段，保留已编辑地址；保存期间的新模型输入保留，下一次普通保存正确返回首页。
- 外部书签标题更新显示在详情中；保留用户正在输入的标题，并采用后台更新的未编辑分类；实际保存结果正确。
- 相同网址、相同文件夹的 A/B 书签，备份条目按 B/A 顺序恢复，分类、摘要和快照仍对应正确；导出文件包含三条书签及两份快照。
- 最终页面检查没有捕获到未处理异常。

浏览器使用隔离的本地页面和测试数据。Chrome API 为替身，生产后台与界面使用真实 Dexie/IndexedDB。模型分类、超时重试、暂停、撤回授权及在途修改由自动测试覆盖，未连接真实模型，也未验证 Chrome 扩展权限弹窗、后台进程重启和用户真实书签库。

复现后台基线时，可执行 `git show 540127e:src/service.ts > /tmp/bookmark-sidekick-service-before-backend.ts`，再运行表中的后台对比命令。
